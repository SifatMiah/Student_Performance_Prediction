# 🎓 Student Early-Warning System

An end-to-end machine learning pipeline that predicts whether a student will **pass or fail** based on lifestyle, academic, and demographic features — paired with a **Streamlit dashboard** for single/batch predictions, SHAP explainability, and a two-level fairness audit.

Built as a final-year university project exploring educational data mining, class-imbalance handling, threshold tuning, and algorithmic fairness.

## Problem Statement

Most students pass — only **4.2 %** fail (42 out of 1 000). A naive classifier that always predicts "Pass" hits 95.8 % accuracy but catches **zero** at-risk students. The goal is an early-warning system that maximises **Fail-class recall** without flooding teachers with false alarms, while remaining transparent and fair across demographic groups.

## Pipeline Overview

### 1 — Exploratory Data Analysis
Distributions, box plots, correlation heatmaps, and value-count audits across all 15 features. Identifies the severe class imbalance and top correlates of exam performance.

### 2 — Preprocessing
- Drop `student_id` (no predictive value)
- Mode-impute `parental_education_level` (91 NaN)
- Winsorise numeric outliers at 1.5 × IQR (attendance and study hours excluded to preserve extreme-risk signals)
- Ordinal-encode categorical features (`diet_quality`, `internet_quality`, `parental_education_level`, etc.)

### 3 — Feature Engineering
Five compound features built from domain reasoning:

| Feature | Formula | Purpose |
|---|---|---|
| `study_x_attendance` | study hrs × attendance / 100 | Joint engagement signal |
| `distraction_hours` | social media + Netflix hours | Total screen-time load |
| `wellbeing_index` | weighted combo of sleep, mental health, diet | Holistic wellbeing proxy |
| `productive_ratio` | study hrs / (distraction hrs + 1) | Productivity balance |
| `at_risk_flag` | attendance < 60 % OR study < 1.5 h | Binary risk trigger |

### 4 — Class Imbalance Handling
Random oversampling applied **inside each cross-validation fold** via `imblearn.Pipeline` to prevent data leakage. No synthetic data touches the validation set.

### 5 — Model Training
Two ensemble classifiers compared via stratified 5-fold CV on ROC-AUC:

| Model | Approach |
|---|---|
| Random Forest | `class_weight='balanced'` + grid search |
| XGBoost / Gradient Boosting | `scale_pos_weight` set to imbalance ratio + grid search |

Best model selected automatically.

### 6 — Threshold Tuning
Default 0.5 threshold is useless at 4.2 % Fail rate. Sweep from 0.05 → 0.75 on Fail-class F1, precision, and recall. Optimal threshold selected to maximise Fail-class F1.

### 7 — Evaluation
- Classification report, confusion matrix, ROC curve at tuned threshold
- Leak-free 5-fold cross-validation scores
- **Bootstrap confidence intervals** (1 000 resamples) — critical given only ~8 Fail cases in the test set

### 8 — Fairness Audit (Two Levels)
- **Label-level:** Demographic parity on raw training labels (gender, parental education) using the four-fifths rule
- **Prediction-level:** Disparate impact ratio, equalised odds (TPR/FPR gap) on model outputs

### 9 — Explainability
- Built-in feature importances
- **SHAP** (TreeExplainer): global summary plot + per-student waterfall charts
- Teacher-facing recommendations mapped to top SHAP drivers

### 10 — Export
Final model retrained on full balanced dataset, then serialised with `joblib` for dashboard consumption.

## Key Design Decisions

**Business-rule overrides** — The training data contains only 13 students with `study_hours = 0`, and 7 of them passed (scores 42–56). This makes the model assign ~50 % pass probability to zero-study students. The dashboard hard-codes an override: 0 study hours → ≥ 95 % fail probability. A similar override fires when attendance < 30 % AND study < 1 h.

**Winsorisation exclusions** — Attendance and study hours are exempt from winsorisation because clamping hides the exact extreme values (e.g., attendance = 0 being pulled up to 58.5) that the early-warning system needs to detect.

**Leak-free CV** — Oversampling happens inside each fold via `imblearn.Pipeline`, not before the split. This prevents inflated scores from duplicated minority samples leaking into validation.

Key evaluation properties:

## Dashboard Features

The Streamlit app (`main.py`) provides three pages:

### 🔍 Single Student Prediction
Adjust sliders and dropdowns for a student's profile → get Pass/Fail prediction with probability bar chart, SHAP waterfall explanation, and actionable teacher recommendations.

### 📋 Batch Prediction
Upload a CSV → get predictions for all students, at-risk ranking, fail probability distribution, override flags, and a downloadable results file.

### ⚖️ Fairness Audit
Two tabs:
- **Label-Level** — pass-rate parity on training data with disparate impact bars
- **Prediction-Level** — upload or use training data to audit model outputs for demographic parity and equalised odds

## Usage

**Single prediction:** Move the sliders, hit Predict, review the SHAP waterfall and teacher recommendations.

**Batch prediction:** Prepare a CSV with the same column names as `student_habits_performance.csv` (minus `student_id` and `exam_score`, which are optional). Upload and download the results.

**Fairness audit:** Use the training dataset or upload your own CSV to check demographic parity and equalised odds across gender and parental education.

## Limitations & Future Work

- **Synthetic data** — The dataset is not from a real LMS/VLE. Feature distributions may not reflect real student populations. Validation on institutional data (e.g., OULAD) is needed before deployment.
- **Small Fail class** — 42 Fail students total, ~8 in the test set. Metrics are volatile; bootstrap CIs help but don't eliminate the problem.
- **Business-rule overrides** — Hard-coded thresholds are brittle. With more data, the model should learn these patterns natively.
- **Static features** — No temporal/sequential data (weekly attendance trends, assignment submission patterns). Time-series models would capture disengagement trajectories.
- **Fairness scope** — Only gender and parental education are audited. Other protected attributes (ethnicity, disability, socioeconomic status) are absent from the dataset.
